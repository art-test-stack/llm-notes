Learning objectives

You should be able to distinguish nominal and effective context length, calculate dense-attention and KV-cache costs, compare efficient attention patterns, explain positional extension and distributed execution, choose between long context and retrieval, and design an evaluation that measures evidence use rather than accepted length.

Four separate problems

“Long context” can mean different things:

  1. the model accepts large position indices;
  2. attention computation and activation memory fit;
  3. the KV cache fits at production concurrency;
  4. the model reliably finds and uses distant evidence.

Solving one does not guarantee the others. A successful 1M-token forward pass establishes nominal support, not useful 1M-token reasoning.

Dense-attention scaling

Let batch size be B, sequence length L, hidden width d, query-head count h, layer count N, KV-head count h_kv, head dimension d_h, and bytes per stored element s.

Cost Approximate scaling Operational meaning
Attention-score memory B h L² s per layer A naïve implementation materializes a score for every head and query-key pair. Flash-style exact attention tiles the calculation and avoids keeping the full matrix, reducing memory without removing the quadratic arithmetic.
Other activations Mostly O(B L d) for each saved tensor Residuals, Q/K/V, normalization, and MLP intermediates are linear in length but numerous. Training retains tensors for backward unless recomputed with activation checkpointing.
Attention prefill FLOPs About 4 B L² d per layer QKᵀ and softmax(QKᵀ)V each contribute about 2 B L² d FLOPs under full-square accounting. A causal kernel that skips the masked triangle can approach half this attention-pair arithmetic. Projections and MLPs add terms linear in L.
Decode KV storage 2 N L h_kv d_h s per sequence The factor 2 stores keys and values. Each decoded token appends one position at every layer, so cache memory grows linearly with generated-plus-prompt length.
Dense decode attention O(L) per new token The new query attends to all cached keys and values. Per-token latency therefore rises with the current context even though only one token is generated.

Worked 128K example

Consider one sequence with L = 131,072, d = 4,096, h = 32, N = 32, grouped-query attention with h_kv = 8, d_h = 128, and bf16 storage (s = 2 bytes):

  • A materialized attention-score tensor for one layer is 32 × 131,072² × 2 bytes = 1 TiB. Across 32 layers, naïvely saving one such tensor per layer would total 32 TiB.
  • One bf16 hidden-state tensor is 131,072 × 4,096 × 2 bytes = 1 GiB. Training saves several activation tensors per layer, so linear terms remain substantial even with tiled attention.
  • Under full-square accounting, the attention core of prefill costs about 4 × 131,072² × 4,096 = 2.81 × 10¹⁴ FLOPs per layer, or about 9.0 × 10¹⁵ FLOPs (9 PFLOPs) across 32 layers, before projections and MLPs. Skipping the masked causal triangle can roughly halve this pairwise term.
  • The decode KV cache is 2 × 32 × 131,072 × 8 × 128 × 2 bytes = 16 GiB per sequence. Each added token grows it by 128 KiB; 16 concurrent sequences at that length would require 256 GiB just for KV.

These are arithmetic and storage quantities, not latency predictions: kernel efficiency, quantized KV, tensor parallelism, and memory bandwidth determine observed performance. See inference and KV cache and serving and request scheduling.

Efficient attention architectures

Approach Long-range mechanism Main gain Main limitation
Dense attention Every query can directly read every earlier token Maximum flexibility and one-hop access Quadratic prefill and linearly growing decode KV
Sliding-window attention Each layer reads the most recent W positions O(LW) attention; old KV can be evicted when every relevant layer is local Distant evidence requires propagation through many layers
Global/local hybrid Local tokens plus selected global tokens or occasional global layers Fast local processing with short paths to summaries or anchors Global capacity can bottleneck; global layers still incur dense cost
Block sparse attention Predefined or routed block-to-block edges Hardware-friendly sparsity and task-specific connectivity The sparsity graph can omit an unforeseen dependency
Dilated or strided attention Heads sample increasingly distant offsets Large receptive field with few edges Fine evidence may fall between sampled positions
Landmark or memory tokens Segments write compressed representations to special tokens Bounded communication channel across long spans Compression is lossy and landmarks can become congested
Recurrent memory Carry hidden state or cached summaries from one segment to the next Potentially unbounded streaming with bounded per-step memory Old details are compressed; training must teach state use and reset semantics
Retrieval Search an external corpus or earlier chunks, then attend densely to selected evidence Small active prompt and independently updateable knowledge Retriever, chunking, or indexing errors can remove needed evidence
State-space alternatives Update a fixed-size recurrent state with linear-time scans Linear sequence processing and compact streaming state Selective recall and arbitrary pairwise comparison are less direct than attention

Receptive-field growth across layers

Efficient patterns should be compared as connectivity graphs, not only by FLOPs. With a causal local window of width W, one layer directly reaches W previous positions and m stacked layers reach roughly mW; the path from old evidence to the current token grows with distance. Exponentially increasing dilation can grow the reachable span roughly exponentially with depth, but uses sparse paths. A global token can connect two distant local regions in about two hops, provided it actually preserves the needed information. Block-sparse patterns depend on their graph diameter, while recurrent and state-space models can have formally unbounded history but a fixed-capacity information channel.

A sliding-window cache may evict old KV only for layers whose pattern never reads it. Hybrid models with global layers need a layer-specific eviction policy; applying one window to every layer is a semantic bug. For a deeper comparison, see state-space models and retrieval-augmented generation.

Long-context positional methods

Method Extension idea Trade-off
RoPE position interpolation Compress new position indices into the range seen during training Extends the range but reduces short-distance angular resolution
NTK-aware or frequency-aware RoPE scaling Scale rotary frequencies non-uniformly so high- and low-frequency dimensions extrapolate differently Preserves more local resolution but introduces a length- and spectrum-dependent design choice
Piecewise or ramped RoPE families Leave some frequencies unchanged, interpolate others, and blend between them; scaling may be fixed or dynamic Can balance local and global behavior, but configuration and maximum target length matter
ALiBi Add head-specific linear penalties based on query-key distance Extrapolates without a learned position table, but its distance prior can discourage very remote evidence
Learned relative bias or buckets Bias attention by relative distance, often grouping large distances into buckets Translation-friendly, but all distances in a coarse far-away bucket may become indistinguishable

Changing the positional rule makes longer indices numerically valid; it does not teach the model to use them. Continued pretraining or staged adaptation on long sequences is normally required to calibrate attention, recover quality, and expose the model to actual long-range dependencies. Training only on repeated or concatenated short documents can teach length tolerance without teaching long-range use.

Always recheck short-context quality. Interpolation compresses nearby positions, aggressive frequency changes alter a representation the model already uses, and a curriculum dominated by long samples can shift the data mixture and optimization regime. Retain a mixture of short and long examples and report quality by length. See RoPE and positional extrapolation.

Long-context training

  • Length curriculum: increase maximum length in stages and mix lengths within stages. This lowers early cost and avoids an abrupt distribution shift, but the final stages must contain enough target-length examples.
  • Batch size and token-batch control: longer sequences reduce the number of sequences that fit per device. Hold global tokens per optimizer step approximately constant with gradient accumulation or an explicit token budget; otherwise learning-rate, gradient-noise, and data-mixture comparisons are confounded.
  • Packing and leakage: packing reduces padding waste, but unrelated documents need boundary-aware attention masks, position resets where appropriate, and loss masking. Allowing one packed document to read another creates cross-document leakage and unrealistic dependencies.
  • Genuine long dependencies: include books, code repositories, long conversations, scientific records, or synthetic tasks where the answer truly depends on remote spans. Mere document concatenation does not supply the learning signal.
  • Optimizer-state continuity: preserve optimizer moments when continuing from a short-context checkpoint unless there is a deliberate reason to reset. Change length, batch, learning rate, and data mixture gradually enough to identify the cause of regressions.
  • Memory techniques: activation checkpointing recomputes forward activations during backward, trading FLOPs for memory. Context parallelism partitions the sequence across devices so no device holds all long-sequence activations.

Distributed long-context execution

Context parallelism partitions the sequence dimension across devices. With P devices, each device owns roughly L/P query positions and their activations, unlike tensor parallelism, which partitions model dimensions. Attention is still exact only if each query can incorporate every causally permitted key/value block.

  1. Each rank computes Q, K, and V for its local sequence block.
  2. In ring attention, each rank keeps its Q block and circulates K/V blocks around a device ring.
  3. For each received block, it applies the causal mask, computes a partial attention result, and updates an online softmax using running maxima and normalization sums.
  4. After the required blocks have visited, each rank holds the exact output for its local queries; later collectives or sequence-parallel layers exchange only what the next operation requires.

This reduces per-device activation and local K/V residency from O(L) to roughly O(L/P), but it does not remove dense attention's total O(L²) work. It trades memory capacity for communication, and is most attractive when transfers overlap with attention kernels.

  • Causal imbalance: early query blocks can attend to few key blocks while late query blocks attend to many. A naïve partition leaves early ranks idle; balanced or zigzag sequence assignment pairs early and late blocks to equalize useful work.
  • Sequence partitioning: layouts must align with tensor, pipeline, and data parallel groups. Transposing between sequence-sharded and hidden-dimension-sharded layouts adds collectives.
  • KV placement at decode: KV may remain sharded by sequence position, reducing per-rank memory but requiring partial attention reductions for every token, or be replicated, spending memory to reduce communication. Grouped-query attention and KV quantization change the break-even point.
  • Communication trade-off: rings offer regular point-to-point traffic and low peak memory, whereas all-gather variants can be simpler but materialize more remote K/V. Interconnect bandwidth, topology, kernel overlap, and small-message latency determine the winner.

See parallelism strategies and serving for the surrounding execution trade-offs.

Long context versus RAG

Criterion Long context Retrieval
Evidence-recall risk Avoids a separate retrieval miss, but the model may fail to notice available evidence Can omit evidence because of embedding, chunking, query, or top-k errors
Prompt and serving cost High prefill, KV, and repeated-input cost Search overhead, but a smaller active prompt and cache
Updateability Prompt contents are current, but repeatedly sending a changing corpus is expensive Index can be updated independently of model weights and most prompts
Distractors Many irrelevant tokens can dilute attention and worsen position effects Filtering reduces distractors, but plausible irrelevant chunks may rank highly
Global synthesis Preserves order, transitions, and broad cross-document relationships Top-k chunks can lose global structure and omitted counter-evidence

Hybrid systems are often strongest: retrieve candidate sections, include neighboring context and source metadata, deduplicate results, and give the model a moderate long window for cross-source synthesis. Retrieval can also page older conversation or memory segments into a recurrent or local-attention model.

Decision framework

Choose When it fits Validate first
Dense long context The corpus fits, arbitrary token-to-token comparisons matter, and misses are costly Prefill/KV budget, concurrency, and middle-position evidence use
Local or sparse attention Dependencies are mostly nearby or follow a known sparse structure Required receptive-field paths and layer-specific cache eviction
Retrieval The corpus is large, changes often, and queries need a small identifiable subset End-to-end recall under realistic queries, chunking, and distractors
Recurrence or state space Streaming or unbounded history matters more than exact access to every old token Memory retention horizon, reset behavior, and compression failures
Hybrid Workloads mix local detail, remote facts, and global synthesis Component interfaces and end-to-end failure attribution, not only isolated scores

A practical selection sequence is: identify the dependency graph; estimate prefill, decode, KV, and communication budgets at target concurrency; decide whether evidence can be indexed; choose the cheapest mechanism that preserves the required paths; then evaluate it on position, length, distractor, and synthesis slices.

Evaluation beyond maximum accepted length

Needle-in-a-haystack is a useful smoke test for addressability, but a single unique string is easy to match and does not test ambiguity, aggregation, causal reasoning, or sustained generation. “Lost in the middle” is a position-dependent failure pattern: evidence near the middle can be used less reliably than evidence near the beginning or end even though every position is nominally visible.

A RULER-style suite broadens the test surface to retrieval with one or several keys or values, multi-hop variable tracing, aggregation, and question answering under long distractor contexts.

Capability Example test Metric Required slices
Nominal support Forward pass and generation at target length Success rate, numerical stability Length and batch/concurrency
Single-span retrieval Needle with paraphrases and plausible decoys Exact match or span F1 Beginning/middle/end positions × context length
RULER-style retrieval and tracing Retrieve keys, follow variable chains, or resolve multi-hop references Accuracy by task category Hop count, key count, position, and length
Aggregation Count, rank, or summarize facts distributed across the context Exact count, set F1, or calibrated error Number and spacing of evidence spans
Multi-evidence reasoning Combine supporting and conflicting spans from several documents Answer accuracy plus citation recall/precision Evidence order, distance, distractor similarity
Long-form consistency Generate a report, story, or code change constrained by earlier details Contradiction rate, constraint retention, entity consistency Output length and dependency distance
Quality across the training boundary Perplexity and downstream tasks below, near, and beyond trained length Quality curves, not one endpoint Short baseline, interpolation range, extrapolation range
System efficiency Prefill and decode at realistic concurrency TTFT, inter-token latency, tokens/s, peak memory, communication volume Prompt length, output length, batch size, hardware count

Keep model, decoding, data, and token budget fixed when comparing lengths. Report full curves or length-position heatmaps: a single average can hide a middle-position collapse, and a single maximum length can hide unacceptable latency or memory.

Failure modes

  • extrapolating positions without long-length training or validation;
  • claiming useful context support from a successful forward pass;
  • ignoring quadratic prefill after fixing score-matrix memory;
  • cache OOM at production concurrency;
  • local or sparse paths blocking required dependencies;
  • distractors overwhelming evidence;
  • cross-document leakage in packed sequences;
  • comparing lengths while changing global token batch, data mixture, or decoding;
  • adding context parallelism without budgeting communication or causal imbalance;
  • treating RAG and long context as mutually exclusive.
