Learning objectives

You should be able to derive the local tensor shapes and collectives for every major parallelism dimension, compare pipeline schedules, construct topology-aware process groups, and explain why production systems combine several dimensions.

Data parallelism as the baseline

Data parallelism (DP) replicates the model and partitions the batch. It raises aggregate throughput but does not reduce model-state memory per rank unless combined with sharded data parallelism. Model-parallel methods instead partition computation or state that cannot fit efficiently on one device. See Distributed LLM Training for gradient synchronization, FSDP, and optimizer sharding.

Tensor parallelism

Let X ∈ R[B,S,H], flatten the token axes as T = B\cdot S, and let a linear layer have W ∈ R[H,O], so Y = XW \in \mathbb{R}^{B,S,O}. For tensor-parallel degree p, assume the partitioned dimension is divisible by p.

Column-parallel linear

Partition the output columns: W = [W_{0} \ldots W_{p-1}], with Wᵢ ∈ R[H,O/p]. Rank i receives replicated Xᵢ ∈ R[B,S,H] and computes Y_{i} = X_{i}W_{i} \in \mathbb{R}^{B,S,O/p}. Concatenation gives Y = \text{concat}(Y_{0},\ldots ,Y_{p-1}).

  • Keep Yᵢ sharded when the next operation is compatible, as in the first MLP projection or QKV projection.
  • Use an all-gather only when every rank needs full Y ∈ R[B,S,O].
  • In backward, each rank produces a partial dXᵢ ∈ R[B,S,H]; summing these contributions requires an all-reduce, or a reduce-scatter over tokens when sequence parallelism wants dX sharded.

Row-parallel linear

Partition the reduction dimension: X = [X_{0} \ldots X_{p-1}] with Xᵢ ∈ R[B,S,H/p], and partition rows of W so Wᵢ ∈ R[H/p,O]. Each rank computes a full-width partial Z_{i} = X_{i}W_{i} \in \mathbb{R}^{B,S,O}, and Y = \sum _{i} Z_{i} + b.

  • An all-reduce of Zᵢ gives replicated Y ∈ R[B,S,O].
  • A reduce-scatter over the flattened token axis instead gives each rank Yᵢ ∈ R[T/p,O]. This is the usual handoff to sequence-parallel residual, dropout, and normalization work.
  • The backward pass naturally produces sharded dXᵢ ∈ R[B,S,H/p]; no gather is needed if it feeds the preceding column-parallel layer.

A column-parallel layer followed by a row-parallel layer therefore keeps the large intermediate sharded and normally pays one reduction at the pair’s output, rather than gathering between the two matrix multiplies.

Attention-head and MLP sharding

Keep query and KV head counts distinct. With Q:[B,H_q,S,D_h] and K,V:[B,H_kv,S,D_h], MHA has H_{q}=H_{\text{kv}}, GQA has H_{q}\gt H_{\text{kv}}\gt 1, and MQA has H_{\text{kv}}=1. For TP=8:

CaseGlobal headsLocal headsKV placement
MHA(H_{q},H_{\text{kv}})=(32,32)Q/K/V each have 4 headsshard all heads
GQA(32,8)Q has 4; K/V each have 1shard when H_kv % TP = 0
MQA(32,1)Q has 4; K/V retain 1replicate the single KV head

If TP\gt H_{\text{kv}} or H_kv % TP != 0, the implementation must replicate KV heads, use uneven or padded ownership, or choose a smaller KV-sharding group. It must not silently assign K/V H_q/TP heads. The output projection remains row-parallel and reduces partial R[B,S,H] results.

For an MLP with intermediate width F, make the gate/up projections column-parallel: Wupᵢ ∈ R[H,F/p] and local activation Aᵢ ∈ R[B,S,F/p]. The down projection is row-parallel with Wdownᵢ ∈ R[F/p,H], followed by one all-reduce or reduce-scatter. SwiGLU shards both gate and value projections on the same F/p axis.

Vocabulary parallelism

Shard an embedding or tied LM-head matrix E ∈ R[V,H] by vocabulary rows: rank i owns Eᵢ ∈ R[V/p,H] and global row offset i·V/p. Input lookup masks tokens outside the local range and all-reduces the selected embeddings. At output, each rank computes local logits Lᵢ ∈ R[T,V/p]. Vocabulary-parallel cross-entropy uses all-reduces for the per-token maximum, exponential sum, and target logit; it does not all-gather R[T,V] logits. Gather only when an API truly needs the full vocabulary distribution.

Sequence-parallel elementwise work

Tensor parallelism otherwise replicates R[T,H] activations around residual, dropout, and normalization operations. Sequence parallelism removes that replication: a row-parallel output reduce-scatters to R[T/p,H], LayerNorm/RMSNorm and dropout run locally because every owned token still has all H features, and an all-gather reconstructs R[T,H] before a column-parallel input. Use rank-aware deterministic RNG for dropout so recomputation reproduces the same mask. This paired reduce-scatter/all-gather has communication volume comparable to an all-reduce while saving replicated activation memory.

Pipeline parallelism

Pipeline parallelism (PP) assigns consecutive layer ranges to P stages and splits a training batch into M microbatches. Activations move forward between adjacent stages and activation gradients move backward. With equal stage times and unit-cost slots, a non-interleaved schedule has roughly P−1 empty fill/drain slots, so its idealized bubble fraction is (P−1)/(M+P−1). Larger M amortizes the bubble, but very small microbatches can reduce kernel efficiency.

ScheduleOrderBubble and memory behavior
GPipeRun all M forwards, then all M backwards.Simple; the same ideal fill/drain fraction, but up to O(M) saved activation sets per stage without recomputation.
1F1BAfter warmup, alternate one forward and one backward; then drain.Similar ideal bubble fraction to GPipe, but only warmup-distance activations remain live, bounded by O(P) rather than O(M).
Interleaved 1F1BGive each physical rank v non-contiguous virtual stages and alternate finer-grained chunks.An optimistic balanced-stage approximation is (P−1)/(M·v+P−1); more stage-boundary transfers and stricter ordering are the price.

The approximation hides unequal forward/backward times, communication, weight-gradient work, and pipeline flushes. Global batch size is commonly DP·M·microbatch_size; choose M ≫ P when possible, then measure rather than trusting the formula.

Activation memory depends on the number of in-flight forwards, tensor shapes at stage boundaries, and whether activations are recomputed. GPipe maximizes the live set; 1F1B releases a microbatch after its backward pass; activation checkpointing trades extra compute for another reduction. Balance stages by measured latency and memory, not layer count alone: embeddings, LM heads, attention at long context, and MoE layers have different costs. A slow stage sets the pipeline clock and creates bubbles even in steady state.

Context and sequence parallelism

Sequence parallelism above is a TP companion for cheap token-wise operations: each rank holds T/p tokens but all hidden features, and collectives occur at TP-layer boundaries. Context parallelism (CP) partitions one sequence for attention itself: with CP degree c, rank j owns Qⱼ,Kⱼ,Vⱼ ∈ R[B,S/c,nₕ,dₕ]. It reduces long-context activation storage approximately by c, but every query block must still attend to the permitted key/value blocks.

Ring attention and KV exchange

  1. Each CP rank computes attention between its fixed local Qⱼ and current K,V block.
  2. It sends that KV block to the next rank and receives another from the previous rank, normally with double-buffered point-to-point communication overlapped with the attention kernel.
  3. After c steps, every query block has seen every allowed KV block; only KV moves, while Q and the output remain owned by the original rank.

The ranks never need to materialize the full score matrix. For one query row, maintain online-softmax state: running maximum m, denominator ℓ, and unnormalized output o. For a new score block s, set m' = \operatorname{max}(m,\operatorname{max}(s)), \ell ' = \operatorname{exp}(m-m')\ell + \sum \operatorname{exp}(s-m'), and o' = \operatorname{exp}(m-m')o + \sum \operatorname{exp}(s-m')V. The final result is o/ℓ. These partial statistics make block order irrelevant up to floating-point effects and pair naturally with fused attention kernels.

A naive causal partition is imbalanced: early query blocks can skip most future KV blocks while late blocks do nearly full work. Zig-zag token assignment, striped blocks, or a causal-aware ring can give each rank a mix of early and late queries. The main savings are roughly 1/c for sequence-sized activations and local KV residency; communication grows with KV traffic, and compute remains quadratic unless the attention pattern itself is sparse. See Long Context for complementary memory and algorithm choices.

Expert parallelism

Expert parallelism (EP) distributes MoE experts across an expert group. If a group has e ranks and N experts, rank r commonly owns N/e experts. For each MoE layer:

  1. The router chooses top-k expert destinations for local tokens.
  2. Tokens are grouped by destination. Ranks exchange per-peer counts, then use an all-to-all with variable split sizes (all-to-all-v semantics) because routing is data-dependent.
  3. Each rank sorts received tokens by local expert, runs the expert MLPs, weights their outputs by router scores, and performs the reverse all-to-all to return results to the token-owning ranks.

Padding every peer to a fixed capacity simplifies kernels but wastes bandwidth; variable splits avoid padding at the cost of count exchange and irregular buffers. Capacity limits, token dropping, and auxiliary balancing losses bound the worst skew. In the usual forward pass, dispatch and combine are two all-to-all phases. Training backward communicates the corresponding activation gradients in reverse, adding collective work; fused or custom-autograd implementations may expose a different API-call count. Expert groups should therefore be kept small and placed on high-bisection-bandwidth links, and communication should be described by phase rather than a universal call count.

EP composes with TP by sharding each expert’s matrices across a TP group; it composes with DP by replicating the full expert set across expert-DP groups and reducing each expert’s gradients only across its replicas. Dense parameters may have a larger data-replica group that spans both DP and EP coordinates because they are replicated across the expert lanes. See Mixture-of-Experts Models for routing and capacity details.

Hybrid process-group construction

A conceptual five-dimensional mesh has world size DP × TP × PP × CP × EP. Give every rank coordinates (d,t,p,c,e). A process group varies one coordinate while holding the others fixed: TP groups vary t, PP groups vary p, CP groups vary c, EP groups vary e, and DP groups vary d. Frameworks sometimes fold EP into the data-parallel axis rather than expose an independent Cartesian dimension; state that convention before quoting a “DP degree.”

Rank numbering is a performance decision. Put the most communication-sensitive coordinate in the fastest-varying bits. TP all-reduces/reduce-scatters are frequent and latency-sensitive, so TP should almost always remain inside one NVLink/NVSwitch domain. MoE all-to-all and CP KV exchange are also high-volume and should remain within a node when the product fits. PP point-to-point transfers and bucketed DP gradient reductions are the usual candidates for crossing nodes. Never assume adjacent global ranks are physically adjacent: construct groups from an explicit rank-to-device/topology map.

Checkpoint portability

A portable checkpoint describes logical tensors independently of the live rank layout. For every shard, record the global shape, dtype, partition axis, shard offset and extent, plus the model configuration and logical parameter name. Reconstruct or stream the global tensor, then repartition it for the destination layout.

  • Changing TP: concatenate old column/row/vocabulary shards along their recorded axes and slice them for the new TP degree. Replicated biases and normalization weights must not be concatenated.
  • Changing PP: parameter ownership moves to the rank holding the layer’s new stage; layer names, not source rank numbers, determine placement.
  • Tied weights: record aliasing between embeddings and the LM head. Restore one logical value and re-establish the tie instead of silently loading divergent copies.
  • Optimizer state: reshard every parameter-aligned moment, master weight, and step counter consistently. Loading weights alone is not a valid training resume.

Validate a migration on a small model with parameter checksums and a forward/backward comparison. A set of rank files can be internally complete yet unusable at a different TP or PP degree if global shapes or offsets are missing.

Worked design: 64 GPUs across 8 nodes

Suppose an MoE Transformer has 64 layers, H=8192, MLP width F=28672, 64 attention heads, vocabulary V=128000, 16 experts, and sequence length S=32768. Each node has 8 strongly connected GPUs; nodes use a high-speed fabric. Choose DP=2, TP=4, PP=2, CP=2, EP=2, whose product is 64.

Use coordinates (d,p,c,e,t) and the row-major mapping rank = ((((d·2)+p)·2+c)·2+e)·4+t. Thus \text{node} = ((d\cdot 2+p)\cdot 2+c), while e∈{0,1} and t∈{0,1,2,3} select the eight GPUs inside that node.

TP4 ranks; fixed d,p,c,e, vary t. A dense [8192,28672] column shard is [8192,7168]; 16 attention heads per rank.Per-block all-reduce or reduce-scatter/all-gather; entirely inside one node.
EP2 ranks; fixed d,p,c,t, vary e. Each EP lane owns 8 of 16 experts, and each owned expert is TP-sharded across four t ranks.Variable-split dispatch and return all-to-all; entirely inside one node.
PP2 stages; fixed d,c,e,t, vary p. Stage 0 owns layers 0–31; stage 1 owns layers 32–63 plus the LM head.Forward activations and backward gradients cross nodes. Use 1F1B with, for example, M=16: ideal bubble ≈ 1/(16+1)=5.9%.

The mapping deliberately spends all eight local GPUs on TP×EP, keeping the most frequent dense collectives and MoE all-to-all on the node fabric. The expected first bottleneck is the inter-node CP KV ring at S=32768; next are MoE imbalance and the stage boundary if one half contains more MoE or long-context work. DP communication is larger but less frequent and can overlap with backpropagation. If profiling shows CP dominates, a reasonable remap is to keep TP×CP inside each node and move EP across nodes—but only if the network handles the resulting irregular all-to-all better. Stage cuts should then be adjusted from measured latency, not fixed at 32 layers.

Selection framework

  1. Does model and optimizer state fit per GPU? If not, start with DP sharding, TP, PP, or EP for the state that dominates.
  2. Do activations fit at the target sequence and microbatch? If not, add checkpointing, sequence parallelism, CP, or PP.
  3. Which tensor dimensions divide cleanly: heads, hidden width, MLP width, vocabulary, experts, layers, and sequence?
  4. What collective runs at each layer, each MoE layer, each stage boundary, and each optimizer step?
  5. Can the most frequent collectives remain on NVLink/NVSwitch, and what must cross the network?
  6. Is the objective capacity, throughput, or latency? Training layouts do not automatically make good distributed inference layouts.

Failure modes

  • TP degree incompatible with query or KV head count, hidden width, MLP width, or vocabulary size;
  • confusing elementwise sequence parallelism with attention-level context parallelism;
  • too few microbatches, large fill/drain bubbles, or excessive GPipe activation memory;
  • pipeline stages balanced by layer count but not by measured time;
  • causal CP assigning most attention work to the last rank;
  • MoE all-to-all dominated by routing skew or padded capacity;
  • topology-unaware rank numbering that sends TP traffic across nodes;
  • checkpoint shards without global shapes, offsets, aliases, or optimizer metadata;
  • assuming more GPUs produce linear speedup.

Review questions

  1. Derive local forward and backward shapes for a column-parallel then row-parallel MLP.
  2. Compare GPipe, 1F1B, and interleaved 1F1B for P=8, M=32.
  3. Derive the online-softmax update used while KV blocks rotate around a CP ring.
  4. Explain why expert dispatch needs variable split sizes and a reverse all-to-all.
  5. Construct rank coordinates and process groups for a topology with two kinds of links.
  6. Describe how to reshard tied weights and optimizer moments when TP and PP both change.
