TL;DR

Applied AI software is often ordinary Python around a model rather than model code itself. The recurring work is to transform records, maintain state, join data by identifiers, rank candidates, batch streams, validate inputs, schedule jobs, cache results, and make failure behavior explicit. The fastest route to reliable code is to choose a representation first, write the simplest correct transformation, test a tiny case, and optimize only when the input scale demands it.

  • Use dictionaries for keyed state, joins, grouping, counters, registries, and caches.
  • Use sets for membership and deduplication; combine a set with a list or deque when order also matters.
  • Use sorting or heaps for ranking, top-k selection, scheduling, and ordered processing.
  • Use generators when the input is a stream or when materializing everything is unnecessary.
  • Use deques for queues and rolling time windows.
  • Make edge cases explicit: empty inputs, duplicates, missing IDs, ties, malformed records, oversized items, stale state, and partial failures.
  • For AI-oriented tasks, separate the domain from the mechanics. A RAG pipeline may reduce to chunking, indexing, ranking, filtering, and joining; an agent orchestrator may reduce to a state machine plus a queue of validated actions.

A practical problem-solving loop

Before reaching for a library, translate the task into four objects: input representation, state, transformation, and output invariant. This is especially useful when the domain description sounds more complicated than the code.

input records
    ↓
choose keys / ordering / state
    ↓
transform one record at a time
    ↓
check invariants on a tiny example
    ↓
handle edge cases
    ↓
optimize only if scale requires it

For example, “aggregate model requests by tenant and keep the most recent successful response” is not fundamentally an LLM problem. It is a dictionary keyed by tenant, an ordering rule on timestamps, and a filter on status.

def latest_success_by_tenant(records):
    latest = {}

    for row in records:
        if row["status"] != "ok":
            continue

        tenant = row["tenant_id"]
        current = latest.get(tenant)

        if current is None or row["timestamp"] > current["timestamp"]:
            latest[tenant] = row

    return latest

Joining two datasets by ID

A frequent mistake is to scan one list inside a loop over another list. Build an index once when you need repeated lookup.

for hit in retrieval_hits:

Deduplication while preserving order

def unique_in_order(values):
    seen = set()
    output = []

    for value in values:
        if value in seen:
            continue
        seen.add(value)
        output.append(value)

    return output

deque

A deque provides efficient append/pop operations at both ends and is ideal for queues and rolling windows.

from collections import deque

def rolling_counts(timestamps, horizon=60):
    window = deque()
    counts = []

    for t in timestamps:
        while window and window[0] < t - horizon:
            window.popleft()

        window.append(t)
        counts.append(len(window))

    return counts

heapq

Python heaps are min-heaps. They are useful when only a small top-k or the next minimum-priority job matters.

import heapq

workers = [(0, "gpu-0"), (0, "gpu-1")]
heapq.heapify(workers)

load, worker = heapq.heappop(workers)
load += job_cost
heapq.heappush(workers, (load, worker))

Sorting, ranking, and deterministic ties

sorted returns a new list; list.sort mutates the existing one. Python sorting is stable, which means equal keys preserve their previous relative order.

ranked = sorted(
    candidates,
    key=lambda item: (-item["score"], item["document_id"]),
)

The tuple key above means: highest score first, then lexicographically smallest document ID. Explicit tie-breaking is valuable in tests and reproducible pipelines.

Top-k choices

  • Small or moderate input: sorted(items, key=..., reverse=True)[:k] is often clearest.
  • Large input with small k: heapq.nlargest or a bounded heap avoids sorting everything.
  • Streaming input: maintain a heap incrementally rather than storing all candidates.

Iterators, generators, and streaming

A generator computes values lazily. This is useful for datasets, event streams, document chunks, token-budget batching, and large files. The main trap is that an iterator can be consumed; a second pass may produce nothing.

def batched(items, batch_size):
    batch = []

    for item in items:
        batch.append(item)

        if len(batch) == batch_size:
            yield batch
            batch = []

    if batch:
        yield batch

Batching by a token or cost budget

def budget_batches(requests, max_tokens):
    batch = []
    used = 0

    for request in requests:
        cost = request["num_tokens"]

        if cost > max_tokens:
            raise ValueError("single request exceeds the budget")

        if batch and used + cost > max_tokens:
            yield batch
            batch = []
            used = 0

        batch.append(request)
        used += cost

    if batch:
        yield batch

Notice that the oversized-single-item policy is explicit. Other valid designs might isolate it, truncate it, or reject it upstream.

Mutability, copying, and aliasing

Many Python bugs are state-sharing bugs rather than algorithmic bugs.

# Bug: every row points to the same inner list.
rows = [[]] * 3
rows[0].append("x")
# [["x"], ["x"], ["x"]]

# Independent lists.
rows = [[] for _ in range(3)]

Mutable default arguments

# Avoid this.
def add_event(event, events=[]):
    events.append(event)
    return events

# Prefer this.
def add_event(event, events=None):
    if events is None:
        events = []
    events.append(event)
    return events

A shallow copy duplicates only the outer container; nested mutable objects remain shared. Use a deep copy only when independent nested state is genuinely required, because copying large structures can itself be expensive.

Functions, dataclasses, and state modeling

Start with functions and simple containers. Introduce a class when the problem has persistent state or invariants that become clearer when encapsulated.

from dataclasses import dataclass, field

@dataclass
class RunState:
    run_id: str
    status: str = "pending"
    completed_steps: list[str] = field(default_factory=list)

    def mark_done(self, step: str) -> None:
        if step not in self.completed_steps:
            self.completed_steps.append(step)

field(default_factory=list) avoids the shared-mutable-default problem.

Useful typing without overengineering

from collections.abc import Iterable, Iterator

def valid_scores(rows: Iterable[dict]) -> Iterator[float]:
    for row in rows:
        score = row.get("score")
        if isinstance(score, (int, float)):
            yield float(score)

Types should make contracts easier to understand. They are not a substitute for runtime validation at external boundaries.

Validation, exceptions, and failure semantics

Validate where data crosses a trust or format boundary: parsed files, tool outputs, user input, service responses, or records from another pipeline stage.

def parse_prediction(row):
    try:
        request_id = str(row["request_id"])
        score = float(row["score"])
    except (KeyError, TypeError, ValueError) as exc:
        raise ValueError("invalid prediction record") from exc

    if not 0.0 <= score <= 1.0:
        raise ValueError("score must be in [0, 1]")

    return request_id, score

Avoid swallowing broad exceptions. A retryable timeout, malformed data, authorization failure, and programming bug should not silently become the same outcome.

Applied-AI patterns expressed as ordinary Python

Retrieval and cosine ranking

import math

def cosine(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    na = math.sqrt(sum(x * x for x in a))
    nb = math.sqrt(sum(y * y for y in b))

    if na == 0 or nb == 0:
        return 0.0

    return dot / (na * nb)


def top_documents(query, documents, k=3):
    scored = [
        (cosine(query, doc["embedding"]), doc["id"])
        for doc in documents
    ]
    scored.sort(key=lambda pair: (-pair[0], pair[1]))
    return [doc_id for _, doc_id in scored[:k]]

Rule-based request routing

Before a learned router is necessary, many routing policies can be expressed deterministically.

def route(request):
    if request.get("needs_tools"):
        return "tool-capable-model"

    if request.get("context_tokens", 0) > 32_000:
        return "long-context-model"

    if request.get("latency_priority"):
        return "fast-model"

    return "default-model"

Time-series window construction

def windows(values, history, horizon):
    stop = len(values) - history - horizon + 1

    for start in range(max(0, stop)):
        x = values[start : start + history]
        y = values[start + history : start + history + horizon]
        yield x, y

For real timestamps, decide separately how to handle gaps, duplicates, irregular intervals, and timezone normalization. Sequence index and elapsed time are not always equivalent.

Agent workflow as a state machine

ALLOWED = {
    "pending": {"running", "cancelled"},
    "running": {"waiting_for_tool", "completed", "failed"},
    "waiting_for_tool": {"running", "failed"},
    "completed": set(),
    "failed": set(),
    "cancelled": set(),
}

def transition(state, new_status):
    if new_status not in ALLOWED[state["status"]]:
        raise ValueError("invalid transition")

    return {**state, "status": new_status}

The model may decide what it wants to do; deterministic Python can still own legal transitions, budgets, validation, retries, and persistence.

Compact exercises for review

For each prompt, first state the input/output contract and the data structure you would use. Then sketch the implementation. The goal is not cleverness; it is fast representation and clean edge-case handling.

1. Latest valid record

Given unsorted model-run records with run_id, version, status, and payload, keep the highest-version successful record for each run_id. Ignore malformed records.

Think about: keyed state, missing fields, tie policy.

2. Dataset leakage prevention

Each example has example_id and customer_id. Produce train/validation sets such that no customer appears in both. Make the split deterministic from a seed.

Think about: grouping before sampling rather than sampling rows independently.

3. RAG candidate merge

Two retrievers return (document_id, score) lists. Merge them, remove duplicates, retain source scores, and return a deterministic top-k according to a simple fusion rule.

Think about: dictionary keyed by document ID, ranking ties.

4. LLM router

Route each request to one of several model descriptors based on required capabilities, maximum context, current availability, and cost. Return a clear error when no model can serve the request.

Think about: filter candidates first, then rank them.

5. Tool workflow

Implement a tiny workflow runner whose steps have IDs and prerequisite IDs. A step can run only when all prerequisites completed. Detect a dependency cycle.

Think about: indegree counts and topological sorting.

6. Token-budget batcher

Consume requests lazily and yield batches whose sum of num_tokens does not exceed a limit. Define behavior for one oversized request.

Think about: generator, accumulator, final flush.

7. Per-user rate limiter

Accept at most five requests per user in any ten-second window. Requests arrive in chronological order.

Think about: dictionary of deques.

8. Data-cleaning pipeline

Normalize whitespace and case in prompts, reject empty prompts, deduplicate normalized content, and preserve the first original version plus its metadata.

Think about: normalization function + seen set.

9. Time-series windows

Given records (machine_id, timestamp, value), build fixed-history/fixed-horizon windows independently per machine. Reject windows crossing a gap larger than a threshold.

Think about: grouping, sorting, gap policy.

10. Worker assignment

Workers have IDs and current load. Jobs arrive with estimated cost. Assign each job to the least-loaded worker, updating load after every assignment.

Think about: heap entries such as (load, worker_id).

11. LRU cache

Implement get and put for a fixed-capacity cache. Accessing a key makes it most recently used.

Think about: OrderedDict; then consider how you would implement it without one.

12. Evaluation summary

Given result records, compute accuracy by model and by task, then identify the model with the best macro-average across tasks.

Think about: nested sufficient statistics; do not retain every row unnecessarily.

13. Conversation memory

Maintain the most recent messages under a character budget. Always retain the system message and remove the oldest ordinary messages first.

Think about: queue semantics and what to do when one message exceeds the budget.

14. Nested error extraction

A tool response is an arbitrary combination of dictionaries and lists. Return all non-empty strings stored under a key named error.

Think about: recursive traversal with explicit base cases.

15. Experiment registry

Runs contain model name, dataset, metric, timestamp, and status. Return the best successful run for each (model, dataset), with latest timestamp as the tie-breaker.

Think about: tuple keys and explicit comparison.

16. Streaming duplicate suppression

Suppress IDs repeated within the last 1,000 events. An ID can occur multiple times inside that window.

Think about: a deque plus counts, not merely a deque plus set.

17. Active-learning selection

Choose the 100 lowest-confidence examples while allowing at most 20 examples from any one source.

Think about: sorting is a fine first implementation; quotas complicate naïve top-k.

18. Spatial nearest centroid

Given 3D points and named centroids, assign every point to its nearest centroid using squared Euclidean distance, then return the point IDs grouped by centroid.

def squared_distance(a, b):
    return sum((x - y) ** 2 for x, y in zip(a, b))

Think about: nested loop is acceptable for the simple version; identify its complexity.

19. Document chunker

Split a token list into chunks of size 200 with overlap 40. Preserve document ID and chunk start/end offsets.

Think about: step size is chunk_size - overlap; guard against invalid overlap.

20. Alert aggregation

Engineering events contain machine, timestamp, severity, and message. For each machine, return its latest error and the number of warnings in the previous hour.

Think about: whether input is sorted, per-machine state, rolling windows.

Final checklist

  • Can I turn a list of records into a dictionary index without thinking?
  • Can I group, count, deduplicate, join, rank, and window data cleanly?
  • Can I explain why I chose a list, set, dict, deque, or heap?
  • Can I recognize when the domain description is hiding a simple data-structure problem?
  • Do I handle empty inputs, duplicates, missing IDs, ties, malformed records, and oversized items?
  • Can my solution accept an iterator when the whole dataset does not need to be materialized?
  • Do I test the smallest non-trivial example before optimizing?
  • If something fails, is the failure mode explicit rather than silently swallowed?
  • For AI systems, are routing, authorization, batching, caching, retries, and state transitions deterministic where possible?
  • Can I state the dominant time and space complexity of the implementation?
