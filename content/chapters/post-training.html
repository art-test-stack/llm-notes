Learning objectives

You should be able to place each post-training method in the complete pipeline, write the central objectives, explain the role of a reference policy and a critic, compare offline preference learning with online RL, and identify failure modes such as reward hacking, length bias, and capability regression.

The post-training pipeline

A common conceptual sequence is:

pretrained model → supervised fine-tuning → preference/reward data
→ offline preference optimization or online RL → safety and capability evaluation

The stages are not mandatory in one fixed order. Continued pretraining may precede SFT; rejection sampling may create better demonstrations; preference optimization can be repeated after new data collection; tool-use or domain-specific SFT may be interleaved with evaluation.

The main distinction is the supervision signal:

  • demonstrations say what response to imitate;
  • comparisons say which of two responses is preferred;
  • scalar rewards score sampled behavior;
  • verifiers provide programmatic outcome signals.

Supervised fine-tuning

SFT maximizes the likelihood of a target response y given a prompt or conversation x. For a decoder-only model, serialize both into one token stream, but supervise only tokens the assistant should generate:

z_i = chat_template(x_i, y_i) = [prompt tokens, response tokens, EOS]
m_it = 1 for supervised assistant-response tokens, 0 otherwise

L_i^sum(θ)  = -Σ_t m_it log π_θ(z_it | z_i,<t)
L_i^mean(θ) = L_i^sum / max(1, Σ_t m_it)
L_SFT(θ)    = (Σ_i w_i L_i) / Σ_i w_i

In a shifted-label implementation, the input at position t predicts the token at t+1. Set labels for system and user tokens, padding, and any unsupervised assistant turns to the framework's ignore index (commonly -100); include the assistant end-of-turn or EOS token. For multi-turn SFT, either supervise every assistant turn or explicitly mask all but the target turn. An off-by-one mask silently trains the model to imitate prompt text or omits the first response token.

Packing, weighting, and length

Packing concatenates several short conversations into one fixed-length training block to avoid padding waste. Record each example boundary, preserve its response mask, and prevent cross-example conditioning with block-diagonal/segment attention when the model supports it. If ordinary causal attention is used, insert unambiguous EOS boundaries and accept that later examples can see earlier ones; never allow the loss or a response mask to spill across a boundary. Position IDs may continue across the packed block or reset per segment, but training and the attention implementation must agree.

The reduction defines the data weighting. A token-mean loss, Σ_i L_i^sum / Σ_i Σ_t m_it, gives long responses more influence. Averaging L_{i}^{\operatorname{mean}} gives each conversation equal weight. Explicit w_i can upweight rare domains or high-confidence demonstrations, but should be logged by source so a small duplicated slice does not dominate. Length normalization changes the optimized distribution; it is a policy choice, not merely a numerical detail.

Truncation should be role-aware. Reserve space for the response and its EOS, preferentially trim expendable prompt context, and avoid retaining a chosen response whose decisive final answer was cut off. For long multi-turn examples, preserve system instructions and the most relevant recent turns. Report truncation rates by source and length bucket. Padding must remain masked from both attention where required and the loss.

Template consistency and demonstration quality

Use the same tokenizer, role markers, generation prefix, BOS/EOS convention, and tool-call serialization during training, rollout, preference scoring, and deployment. A template mismatch is distribution shift at the first generated token; duplicated BOS tokens or missing end markers can undo otherwise correct training.

SFT teaches format, style, tool schemas, domain procedures, and instruction following, but it also imitates mistakes. A smaller set of correct, diverse, instruction-consistent demonstrations can beat a larger noisy set; contradictory answers, templated verbosity, answer leakage, and duplicated synthetic examples are learned as behavior. Audit quality by source and use filtering or verification as described in Synthetic Data Generation and Filtering.

Teacher forcing conditions on gold prefixes during training, whereas generation conditions on the model's own sampled tokens. This exposure bias permits early errors to move the model into unseen states and compound. Better coverage of recovery behavior, model-generated-prefix training, rejection sampling, or later on-policy optimization can help, but each changes the training distribution and needs independent evaluation.

Preference data construction

A preference record should retain the prompt, both complete responses, the sampling policies and decoding settings, presentation order, annotator identity or pool, raw votes, tie/skip options, rubric version, and provenance. Construct pairs for the same prompt so the label isolates response quality. Mix obvious quality gaps with close decisions: only easy pairs saturate the loss, while only ambiguous pairs produce noisy gradients.

  • Pair construction: sample candidates from one or more checkpoints, deduplicate near-identical answers, stratify by task and difficulty, and keep rejected responses plausible. Pairing a polished answer only against broken text teaches coarse artifacts rather than fine preference.
  • Ties and indifference: let annotators declare a tie or insufficient information. Preserve ties with a tie-aware model or soft target near 0.5, or exclude them while reporting the exclusion rate. Forcing every tie into a binary winner injects random labels.
  • Disagreement: retain vote counts rather than only majority labels. Estimate agreement by slice, re-adjudicate high-impact conflicts, and distinguish genuine plural preferences from unclear rubrics or low-quality annotation. Soft empirical win rates can train a probabilistic reward model.
  • Position and length bias: randomize or counterbalance left/right order, blind model identity, and audit label rate against response length, formatting, confidence language, citations, and refusal position. Include length-matched pairs and counterexamples where the concise answer is better.
  • Active sampling: prioritize pairs with ensemble disagreement, reward scores near a decision boundary, novel clusters, or high deployment impact. Correct for the resulting non-random sampling when estimating population metrics; uncertainty-only sampling can repeatedly select irreducibly ambiguous examples.
  • On-policy versus off-policy: current-policy responses match the behavior being improved and expose new failures, but require recurring collection. Older or external responses are cheaper and more diverse, but their errors and likelihood ratios may be unlike the current policy. Track policy provenance and refresh data when win-rate or reward-model calibration shifts.

Label-quality audits should include hidden gold or adjudicated items, repeated items for intra-annotator consistency, duplicate pairs with swapped positions, rubric-comprehension checks, slice-level disagreement, and manual review of high-loss or high-influence examples. Hold out prompts, not merely pairs from prompts seen in training, to prevent leakage.

Reward modelling

A reward model maps a prompt-response pair to a scalar. Bradley–Terry follows from a random-utility model. Give each candidate latent utility u_j = r_φ(x,y_j) + ε_j, with independent type-I extreme-value noise. The difference of the noise variables is logistic, hence:

P(y_w ≻ y_l | x) = P(u_w > u_l) = σ(r_φ(x,y_w) - r_φ(x,y_l)) L_RM(φ) = -q log σ(Δr) - (1-q) log σ(-Δr) Δr = r_φ(x,y_w) - r_φ(x,y_l)

Here q=1 is a hard winner and q may instead be an empirical win fraction. Only reward differences occur, so r'(x,y)=r(x,y)+c(x) gives identical probabilities: the scalar is identifiable only up to a prompt-dependent additive constant. Its scale is also tied to the assumed noise temperature. Absolute reward values therefore do not transfer automatically across checkpoints or datasets.

Scaling, uncertainty, and shift

Before policy optimization, estimate reward mean and variance on a fixed reference distribution and apply a documented centering/scaling or clipping rule. Whitening rollout rewards can stabilize advantages, but batch-relative normalization makes a score's meaning depend on batch composition. Do not use post-normalization means to claim product improvement; retain raw and normalized components and periodically re-anchor them to a frozen evaluation set.

Train independently seeded or bootstrapped reward-model ensembles and inspect both mean reward and disagreement. High ensemble variance can drive active data collection, abstention, or conservative penalties. It is only a heuristic for epistemic uncertainty: correlated architectures trained on the same biased labels can agree and still be wrong. Measure preference probability calibration and selective accuracy using the methods in Hallucination, Grounding and Calibration.

The policy changes the response distribution presented to a frozen reward model. This distribution shift can turn harmless shortcuts—length, confident tone, copied rubric phrases, or verifier edge cases—into optimization targets. As optimization pressure grows, proxy reward can rise while true quality falls (overoptimization). Detect reward hacking with held-out human judgments, independent reward models, adversarially generated candidates, length-controlled slices, and periodic on-policy relabeling; no single learned reward should both define and certify success.

PPO-style RLHF

PPO performs online optimization on sampled responses. For prompt x, a token-level trajectory is s_t=(x,a_1,…,a_{t-1}), action a_t is the next response token, and the episode ends at EOS or a length limit. Prompt and padding positions are masked from policy and value losses. A common reward decomposition places the task or reward-model score at the final valid token and a dense sampled KL penalty at every generated token:

k_t = log π_old(a_t|s_t) - log π_ref(a_t|s_t) r_t = -β k_t + 1[t=T] R(x, a_1:T)

This sampled log-ratio is an unbiased forward-KL estimate only when actions are sampled from the policy named in the expectation. Some implementations instead add KL as a separate loss. Do not accidentally apply both at full strength.

Return, value function, and GAE

The return from token t and the critic's target quantity are:

G_t = Σ_{l=0}^{T-t} γ^l r_{t+l} V_ψ(s_t) ≈ E[G_t | s_t]

A Monte Carlo advantage G_t-V(s_t) is unbiased under the sampled policy but high variance. Temporal-difference residuals bootstrap from the critic:

δ_t = r_t + γ(1-d_t)V_ψ(s_{t+1}) - V_ψ(s_t)

where d_t=1 at a true terminal state. Repeatedly substitute the next-step residual. Generalized advantage estimation exponentially weights the resulting multi-step corrections:

Â_t^GAE(γ,λ) = δ_t + γλ(1-d_t)δ_{t+1} + (γλ)^2(1-d_t)(1-d_{t+1})δ_{t+2} + … = Σ_{l=0}^{T-t} (γλ)^l δ_{t+l} V̂_t = Â_t + V_old(s_t)

\lambda =0 gives low-variance one-step TD; \lambda \to 1 approaches a Monte Carlo correction and reduces bootstrap bias. For truncated responses, distinguish a real terminal EOS from a time-limit truncation: bootstrapping may be valid at the latter. Normalize advantages over valid response tokens only, and inspect the unnormalized distribution too.

Clipped losses and updates

ρ_t(θ) = exp(log π_θ(a_t|s_t) - log π_old(a_t|s_t)) J_policy = E_t[min(ρ_t Â_t, clip(ρ_t, 1-ε, 1+ε) Â_t)] L_value = E_t[max((V_ψ-V̂_t)^2, (clip(V_ψ-V_old,-ε_v,ε_v)+V_old-V̂_t)^2)] J_entropy = E_t[H(π_θ(·|s_t))] L_total = -J_policy + c_v L_value - c_H J_entropy

Clipping prevents a sample from creating an arbitrarily large surrogate improvement after its probability moves too far; it is not a hard trust region. Value clipping is optional, and entropy encourages exploration but can fight deterministic-format requirements. Track policy and value clip fractions, explained variance, advantage statistics, gradient norms, and per-token entropy.

Useful approximate KL diagnostics include the sampled k_{1}=\operatorname{log} \pi _\text{old}(a\mid s)-\operatorname{log} \pi _\text{new}(a\mid s), which is noisy and can be negative per sample, and the non-negative approximation k_{3}=(\rho -1)-\operatorname{log} \rho. Measure KL to both the rollout policy (update size) and the fixed reference (behavioral drift), using response masks.

An adaptive reference-KL controller can update \beta toward target K*, for example \beta \leftarrow \beta \operatorname{exp}(\eta \operatorname{clip}(K/K^{\ast} - 1,-c,c)). If observed KL is high, increase the penalty; if low, decrease it. Smooth the measurement and bound the update because short noisy batches can otherwise make the controller oscillate.

Collect rollouts under frozen \pi _\text{old}, compute rewards and advantages once, then perform several shuffled PPO epochs and minibatches while keeping old log-probabilities and targets fixed. Too many epochs make data stale and drive ratios into the clip boundary; too few waste expensive rollouts. Recompute new log-probabilities with exactly the same tokenization and masks, stop early on excessive policy KL, and never mix prompt/padding tokens into token-count denominators.

Direct Preference Optimization

DPO starts from reward maximization regularized toward a fixed reference policy. For each prompt, optimize over normalized response distributions:

max_π E_{y~π(·|x)}[r(x,y)] - β KL(π(·|x) || π_ref(·|x))

Add a Lagrange multiplier for \sum _y \pi (y\mid x)=1 and set the derivative with respect to \pi (y\mid x) to zero. The optimum is an exponentially tilted reference:

π*(y|x) = π_ref(y|x) exp(r(x,y)/β) / Z(x) r(x,y) = β[log π*(y|x) - log π_ref(y|x)] + β log Z(x)

Insert this implicit reward into the Bradley–Terry preference probability. The prompt-only partition term cancels between chosen and rejected responses:

Δ_θ = [log π_θ(y_w|x) - log π_ref(y_w|x)] - [log π_θ(y_l|x) - log π_ref(y_l|x)] P_θ(y_w ≻ y_l | x) = σ(β Δ_θ) L_DPO = -E_(x,y_w,y_l) log σ(β Δ_θ)

This is a classification loss for a policy parameterization of the implicit reward, avoiding an explicit reward model, online rollouts, and critic. Under the derivation, \beta is the coefficient on KL: larger \beta means stronger regularization for fixed reward units, while in the DPO logit it also sets the relative-log-ratio scale. Its practical effect depends on optimization, data separability, and learning rate, so select it using held-out preference and drift metrics rather than interpreting it in isolation.

Sequence probabilities, length, and the reference

log π_θ(y|x) = Σ_{t=1}^{|y|} log π_θ(y_t | x,y_<t)

Compute this sum over response tokens and the response EOS only; prompt, padding, and packed neighbors are masked. Chosen and rejected responses must use the same serialized prompt and generation prefix. Cache reference log-probabilities only if tokenizer, truncation, and template versions are immutable and recorded.

Because sequence log-probability is a sum, its scale grows with length. The reference-relative difference cancels some shared length effects, but not a policy/reference mismatch in verbosity or EOS behavior. Report accuracy and margin by chosen-minus-rejected length, construct length-controlled pairs, and monitor generated length. Dividing log-probability by token count or adding an explicit length penalty can reduce length sensitivity, but changes the sequence-level KL derivation and should be treated as a new objective.

Reference-free variants remove the reference terms, use a constant/uniform baseline, or rely on chosen-response likelihood as an anchor. They save reference inference and can be useful when no suitable reference checkpoint exists, but lose the explicit density-ratio interpretation. Raw sequence likelihood strongly reflects length and common phrasing; without an anchor the policy can drift, forget capabilities, or increase both chosen and rejected likelihoods in unintended ways. Measure KL to a frozen base even if the training loss does not use it.

Additional offline preference objectives

These methods change which weakness of pairwise DPO they address. They are most useful as different inductive biases, not as interchangeable acronyms.

ObjectiveCore mechanismWhat it buysMain caution
IPORegress the reference-relative chosen/rejected log-ratio toward a finite target, schematically (\Delta _\theta - 1/(2\beta ))^{2}.Avoids driving separable pairs toward an unbounded logistic margin; ties naturally to a regularized preference formulation.The target and scale are sensitive to \beta, label noise, and convention; it still needs paired data and usually a reference.
KTOClassify individual responses as desirable or undesirable using a prospect-theoretic utility relative to a KL-derived baseline.Can learn from unpaired binary feedback and weight positive/negative examples asymmetrically.Baseline estimation and class balance matter; binary labels discard within-prompt ranking information and do not remove off-policy coverage limits.
ORPOCombine chosen-response SFT with a reference-free odds-ratio preference penalty.The SFT term anchors the policy while the odds ratio separates chosen from rejected, avoiding a second reference forward pass.Sequence odds can be poorly scaled, and the chosen-only anchor may reinforce demonstration artifacts or permit more drift than an explicit reference.
SimPOUse a target-margin logistic loss on the difference of length-normalized chosen and rejected log-probabilities.Removes reference inference and directly controls average per-token preference and margin.Length normalization changes the probabilistic target; reference-free updates need explicit capability and KL monitoring.

IPO mainly caps the incentive to increase an already-correct pair margin. KTO changes the data interface by accepting unpaired good/bad examples. ORPO and SimPO change the anchor: the former couples preference learning to chosen-response SFT, while the latter uses a reference-free, length-normalized margin. Compare them on the same held-out prompts, response-length slices, base-model KL, and independent capabilities; a higher training pair accuracy alone does not identify the better policy.

Group Relative Policy Optimization

GRPO means Group Relative Policy Optimization. For each prompt, sample G completions from the rollout policy, score them with a learned reward or verifier, and use their within-prompt relative performance instead of a learned value function. Sampling temperature and duplicate rate determine whether the group contains useful variation:

x → y_1,…,y_G R_i = R(x,y_i) μ_R = (1/G)Σ_i R_i σ_R = sqrt((1/G)Σ_i(R_i-μ_R)²) Â_i = (R_i-μ_R) / (σ_R+ε)

Centering creates a prompt-specific baseline and scaling prevents high-variance prompts from dominating. It also discards absolute difficulty: a mediocre answer can be positive if its group is worse. With sparse binary rewards, groups in which every sample passes or every sample fails have \sigma _R=0 and no within-group learning signal. Adding epsilon avoids division by zero but does not create information; set their advantages to zero or skip them, log the rate, and improve sampling difficulty or reward shaping.

Token objective, clipping, and KL

ρ_it(θ) = π_θ(y_it|x,y_i,<t) / π_old(y_it|x,y_i,<t) J_GRPO = E_{i,t}[min(ρ_it Â_i, clip(ρ_it,1-ε,1+ε)Â_i) - β KL_it(π_θ || π_ref)]

The simplest scheme broadcasts one sequence advantage Â_i to every response token. Token averaging then means long completions contribute more token terms unless the implementation first averages within each sequence. Token-level credit can instead use process rewards, per-step verifier signals, or return-to-go, but then the method is no longer using only a terminal group-relative score and must align reward positions carefully.

As in PPO, clipping limits updates relative to the rollout policy, not the fixed reference. KL can be applied as a sampled per-token reward, an explicit loss, or an unbiased/full-distribution estimator where affordable. State which policy pair and direction is measured, mask prompts and padding, and avoid double-counting. An adaptive controller can target reference KL, while rollout-policy KL remains an early-stopping signal.

Removing the critic saves value-model parameters and value fitting, not rollout compute. Each prompt requires G generations, reference and reward/verifier evaluation, and often several update epochs; cost grows roughly with total generated tokens and group size. Larger groups estimate relative rank better but reduce prompt diversity for a fixed token budget.

GRPO is especially effective with reliable outcome verifiers, as in mathematical or code reasoning training. It is also verifier-dependent: false positives, brittle parsers, leaked tests, style rewards, or partial-credit errors become optimization targets. Use hidden tests, verifier ensembles or mutations, contamination checks, and human audits of high-reward failures.

Parameter-efficient adaptation

LoRA represents an update as a low-rank product:

W' = W + (α/r) B A

The base weights remain frozen while low-rank factors are trained. Savings are strongest for trainable parameters, gradients, optimizer state, and adapter checkpoints. The frozen base model still participates in forward/backward computation, and activation memory remains.

QLoRA stores the frozen base in a quantized representation while training LoRA adapters. It lowers adaptation memory but depends on quantization-aware kernels and does not imply that every tensor is low precision.

Failure modes

  • demonstrations with incorrect loss masks or template mismatch;
  • preference pairs dominated by superficial style;
  • reward model exploiting length or confidence language;
  • PPO value instability or KL collapse;
  • DPO overfitting narrow comparisons;
  • GRPO groups with little reward variance;
  • reward hacking and verifier loopholes;
  • catastrophic forgetting of base capabilities;
  • reduced diversity or mode collapse;
  • using one reward curve as the only evaluation.

Evaluation and monitoring

Evaluation must separate the optimization proxy from the desired behavior. Freeze prompts, judges, and scoring code for comparable checkpoints, but also add fresh and adversarial prompts to detect adaptation to the suite. Report confidence intervals, paired differences on identical prompts, slice results, and the full sampling configuration. See LLM Evaluation and Benchmark Design for judge bias, contamination, and statistical testing.

For every training run, plot reward beside independent success, reference KL, entropy, response length, and safety regressions over steps. A rising reward with falling independent success is the signature to stop, relabel, or replace the proxy. Calibration should be checked by domain and shift, not only as one aggregate number; see Hallucination, Grounding and Calibration. Synthetic or model-judged evaluation data needs provenance, leakage checks, and human spot audits as in Synthetic Data Generation and Filtering.
