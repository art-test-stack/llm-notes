Learning objectives

You should be able to construct RoPE frequencies, derive the relative-position identity in real and complex notation, implement the common layout and cache variants, and evaluate long-context extensions for both quality and numerical correctness.

Frequency construction

Let the even rotary width be d, let i=0,\ldots,d/2-1 index feature pairs, and usually set b=10{,}000. The angular frequency of pair i, in radians per token, is:

inverse_freq_i = base^(-2i/d) θ_i = inverse_freq_i

For positions p=(p_0,\ldots,p_{T-1}), form the position-frequency outer product:

angles[p, i] = p × inverse_freq_i
angles = outer(position_ids, inverse_freq)     # [T, d/2]

The first pairs have the largest \theta_i and rotate fastest; later pairs have progressively smaller frequencies and rotate more slowly. A pair's wavelength is \lambda_i=2\pi/\theta_i tokens: positions separated by one wavelength have the same phase in that pair. Fast dimensions distinguish nearby offsets finely but wrap often. Slow dimensions vary little locally but retain phase information across longer spans. RoPE combines many wavelengths; no single pair uniquely identifies every possible offset.

Core rotation

For one pair (x_0,x_1) at position p and frequency \theta:

[x'₀] [ cos(pθ) -sin(pθ) ] [x₀] [x'₁] = [ sin(pθ) cos(pθ) ] [x₁]

Write this matrix as R(p\theta). Since rotations are orthogonal and compose by adding angles:

(R(pθ)q)ᵀ(R(sθ)k) = qᵀ R(pθ)ᵀ R(sθ) k = qᵀ R((s - p)θ) k

Summing this identity over all pairs makes each query-key dot product depend on the relative offset s - p through several frequencies.

Complex-number derivation

Identify a real pair with a complex number: z=x_0+ix_1. Rotation at position p is multiplication by a unit phasor:

z̃_p = z exp(i pθ) = (x₀ + i x₁)(cos(pθ) + i sin(pθ))

For complex query and key pairs q and k, their two-dimensional real dot product is the real part of one value times the other's conjugate:

dot(q̃_p, k̃_s) = Re[(q exp(i pθ)) conjugate(k exp(i sθ))] = Re[q conjugate(k) exp(i (p - s)θ)]

The phase therefore depends on relative displacement, not the two absolute indices separately. More precisely, RoPE makes this positional contribution to an attention logit invariant to a joint shift (p,s)\mapsto(p+c,s+c). It does not make the whole model translation invariant: token content, causal and padding boundaries, finite windows, cache eviction, special tokens, and layers outside this dot product can distinguish absolute placement. Nor are logits invariant if only the query or only the key is shifted.

Implementation variants

Choice Common conventions and constraints
Pairing layout Interleaved pairs adjacent features (0,1), (2,3), …. Split-half pairs feature j with j + d/2. They implement the same mathematics after a permutation, but a checkpoint and backend must agree on the convention.
Partial rotary width Only an even prefix d_rot ≤ D_h is rotated; the remaining features pass through unchanged. Construct frequencies using the checkpoint's configured rotary width and denominator convention.
Rotated tensors Apply RoPE to Q and K only. V is not part of the query-key dot product and is normally left unrotated.
GQA/MQA Q may have H_{q} heads while K has H_{\text{kv}}. Broadcast one position table across each tensor's head axis independently; do not require equal head counts or materialize repeated K merely to apply RoPE.
Padded batches Pass explicit position IDs shaped [B,T]. With left padding, valid-token positions can be derived from cumsum(attention_mask) - 1, with pad entries clamped or ignored. Raw column indices incorrectly shift shorter prompts.
Key-cache convention A rotated cache stores K after RoPE and never rotates old keys again. An unrotated cache stores projected K plus enough position metadata to rotate it when read. The latter permits some remapping schemes but costs work; mixing the two conventions silently corrupts logits.

Implementation pseudocode

This sketch makes position IDs, rotary width, pairing convention, and cache state explicit. pair/unpair are layout adapters: adjacent even/odd features for interleaved layout, or corresponding first/second halves for split-half layout.

def rope(x, position_ids, d_rot, base, pairing):
    # x: [B, H, T, D_h]; position_ids: [B, T]; d_rot is even
    x_rot, x_pass = x[..., :d_rot], x[..., d_rot:]

    i = arange(0, d_rot // 2, dtype=float32)
    inverse_freq = base ** (-2 * i / d_rot)
    angles = position_ids.to(float32)[..., None] * inverse_freq[None, None, :]
    cos = cos_fp32(angles)[:, None, :, :]       # [B, 1, T, d_rot/2]
    sin = sin_fp32(angles)[:, None, :, :]

    a, b = pair(x_rot.to(float32), convention=pairing)
    y_rot = unpair(a * cos - b * sin,
                   a * sin + b * cos,
                   convention=pairing)
    return concat(y_rot.to(x.dtype), x_pass, dim=-1)

def project_and_cache(x, position_ids, cache):
    q, k, v = project_qkv(x)                    # H_q may differ from H_kv
    q = rope(q, position_ids, d_rot, base, pairing)
    k = rope(k, position_ids, d_rot, base, pairing)
    cache.append_rotated(k, v, position_ids)    # choose and document one convention
    return attention(q, cache.k, cache.v)

Production kernels may fuse these operations and avoid temporary FP32 tensors. The observable contract—pairing, position mapping, precision, and cache convention—must remain the same.

Cached decoding and position semantics

During ordinary prefill, valid tokens use positions 0 … T-1. The next decoded token uses the next logical absolute position. With padding, batching, prefix reuse, or packed inputs, that value must come from per-sequence position metadata rather than a single tensor length.

After sliding-window eviction, len(cache) is at most the window size and is no longer the total number of consumed tokens. Continue the model's absolute position counter unless it was explicitly trained with position resets. Resetting only the new query and key while retaining previously rotated keys changes their relative phases. A deliberate reset requires a coherent scheme—for example, rerotating every retained unrotated key with the same new origin—and must match training semantics.

Long-context extensions

All scaling names are implementation-dependent, so inspect the exact equations in a checkpoint's configuration. In particular, fixed-factor position interpolation and “linear RoPE scaling” are often two APIs for the same global transform, even though the motivation may be described differently.

Method Intuition Trade-offs
Position interpolation For extension factor \alpha = L_{\text{new}}/L_{\text{train}}, use p' = p/\alpha, compressing the longer sequence into the trained position range. Avoids unseen maximum angles but reduces resolution between nearby positions; usually benefits from adaptation training.
Linear scaling Use \theta '_i = \theta _i/\alpha. For a fixed factor this is mathematically equivalent to globally scaling positions. Simple and predictable, but applies the same stretch to fast and slow bands and can regress short-context behavior.
NTK-aware scaling Adjust the RoPE base so dimensions are stretched non-uniformly, aiming to preserve more local resolution while extending slower modes. Often preserves short-range behavior better than uniform scaling, but the formula and calibration vary by implementation and model.
Dynamic NTK variants Choose the scaling or base from the current sequence length, often leaving short sequences unchanged and activating beyond the training window. Adapts across lengths, but changing the frequency map after keys have been cached can invalidate their phases. Prefill, decode, and cache reuse must use one consistent map.
YaRN-style band treatment Treat frequency bands differently: interpolate some wavelengths, extrapolate others, blend a correction range, and optionally rescale attention magnitude. Offers finer control over local versus global behavior, at the cost of more hyperparameters and backend/checkpoint compatibility requirements.
Long-context continued training Expose the model to long sequences using the intended scaling rule and data with genuinely long dependencies. Can teach effective evidence use rather than merely valid phases, but consumes training compute and may shift the data mixture or short-context quality.

No method is universally optimal. The choice depends on the extension factor, whether weights can be trained, required local resolution, cache behavior, serving kernels, and measured quality across both short and long inputs. Scaling only changes positional geometry; it does not solve quadratic attention cost, KV-cache memory, or weak use of distant evidence.

Numerical behavior

  • Large positions: the product p_{\theta_i} grows, so finite-precision argument reduction for sine and cosine can accumulate phase error even though the returned values remain bounded.
  • BF16/FP16: large integers cannot represent every adjacent position in these formats. Casting positions or angles too early can make distinct tokens share a phase or introduce abrupt errors.
  • Wider angle path: construct inverse frequencies, multiply positions, and evaluate trigonometric functions in at least FP32 (or wider where justified), then cast sine/cosine or the rotated output to the model dtype. Validate fused kernels against this reference.
  • Cache offsets: track the logical per-request position separately from physical cache length, especially after eviction, prefix reuse, batching, or speculative rollback.
  • Sliding windows and resets: an absolute-position window retains the original phases of surviving keys. A reset-position window changes the model semantics and requires all compared Q/K positions to share the new origin; it is not a harmless bookkeeping optimization.

Evaluation

Probe What to report
Perplexity by length Bucket held-out sequences by length, including below, near, and beyond the training window; report both mean and degradation curves.
Needle retrieval Vary total length, needle position, number of needles, and distractor similarity. Separate exact retrieval from generation-format failures.
Position-sensitive tasks Test order, recency, counting, and evidence at beginning/middle/end to reveal positional bias and phase-resolution failures.
Multi-hop evidence Place required facts far apart and add plausible decoys; score synthesis separately from single-span lookup.
Short-context regression Repeat the original short-context evaluation after scaling or continued training; an extension is not free if common-case quality falls.
Accepted versus effective length Distinguish the longest input that completes a forward pass from the longest length at which quality meets a predeclared threshold. Also report memory and latency.

Implementation test suite

  1. Position zero: for random FP32 tensors and every supported pairing/layout, assert rope(x, 0) == x; include partial rotation and verify the pass-through tail bit-for-bit.
  2. Norm preservation: compare the L2 norm of every rotated pair before and after RoPE at small and large positions. Use dtype-specific tolerances and a high-precision reference.
  3. Relative/offset equivalence: check \text{dot}(R_{p} q, R_{s} k) \approx \text{dot}(q, R_(s-p) k), then jointly add several offsets c and verify the dot product is unchanged. Include negative relative offsets and non-contiguous position IDs.
  4. Cached versus uncached logits: run a tiny deterministic decoder once on the full causal sequence and once token by token. Compare logits at every step, not just sampled tokens, for rotated and unrotated cache implementations.
  5. Cache-offset cases: repeat the logit comparison with left-padded unequal prompts, a nonzero prefix offset, sliding-window eviction, and speculative append/rollback. Assert positions follow logical token count rather than physical cache length.
  6. GQA shapes: test H_q/H_kv ratios such as 8/2 and MQA 8/1, batch size greater than one, multiple sequence lengths, and partial rotary width. Assert Q and K shapes are preserved and each KV head receives the same position phases as its query-head group.
  7. Padding positions: compare a sentence alone, right padded, and left padded. After masking pads, logits for its valid tokens should agree when explicit position IDs are constructed correctly.
  8. Backend-convention compatibility: create golden outputs from a simple FP32 reference for interleaved and split-half pairing, rotary width, base/scaling rule, tensor layout, and cache convention. For each optimized backend, load only its matching fixture and compare forward and cached-decode outputs; also assert that a deliberately mismatched convention fails the comparison.
  9. Precision stress: compare FP32 reference phases and logits against BF16/FP16 execution at positions around the training limit and the advertised maximum. Set tolerances from observed error budgets and fail on NaNs, infinities, or adjacent-position collapse.

Failure modes

  • using the wrong denominator or base for checkpoint frequencies;
  • mixing interleaved and split-half pairing;
  • applying RoPE to V or to an unconfigured feature tail;
  • broadcasting K as if H_kv == H_q under GQA;
  • deriving left-padded position IDs from raw tensor columns;
  • resetting decode offsets or using physical cache length after eviction;
  • storing rotated keys and rotating them again;
  • changing a dynamic scaling map while reusing keys rotated under the old map;
  • computing large angles directly in BF16/FP16;
  • equating an accepted context length with reliable evidence use.

Review questions

  3. Implement partial RoPE for both pairing conventions and explain the GQA broadcast.
  4. Diagnose divergence between cached and uncached decoding after window eviction.
  5. Compare position interpolation, NTK-aware scaling, and YaRN-style treatment, then design an evaluation that separates accepted from effective length.
