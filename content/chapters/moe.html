Learning objectives

You should be able to derive sparse top-k routing and its balancing loss, compare token-choice and expert-choice variants, work a routing-and-capacity example, distinguish semantic specialization from harmful systems imbalance, and connect MoE architecture to expert-parallel all-to-all communication.

Core idea

An MoE Transformer replaces selected dense feed-forward layers with multiple experts and a router. For token representation x:

router_logits = W_r x
selected = top_k(router_logits)
y = Σ_{e in selected} gate_e(x) · expert_e(x)

Only a small subset of experts is active per token. This increases total parameter capacity without making active FLOPs proportional to total parameters.

Router mathematics

Let x_t be token t's hidden state and let there be E experts. A linear router produces one logit per token and expert:

z_{t,e} = (W_r x_t)_e softmax gate: p_{t,e} = exp(z_{t,e}) / Σ_j exp(z_{t,j}) sigmoid gate: s_{t,e} = σ(z_{t,e})

Softmax probabilities compete and sum to one. Sigmoid scores are independent and need not sum to one; this can reduce forced competition, but their scale must be handled when combining experts. In either case the router can select S_t = TopK(scores_t, k). Top-1 selects one expert; top-2 permits two expert contributions and a fallback destination at greater compute and communication cost.

A common combine rule renormalizes only the selected scores:

g_{t,e} = q_{t,e} / Σ_{j ∈ S_t} q_{t,j} if e ∈ S_t, else 0 y_t = Σ_{e ∈ S_t} g_{t,e} Expert_e(x_t)

Here q may be the softmax probability p or sigmoid score s. For top-1, selected-set renormalization makes g=1; some implementations instead retain the raw selected probability as a multiplier so the task loss still supplies a gate-magnitude gradient.

Gradient flow

  • The hard TopK index operation is discontinuous. Ordinary backpropagation treats the chosen set as fixed; it does not differentiate through the counterfactual choice of another expert.
  • Selected expert parameters receive task-loss gradients through their weighted outputs. Unselected expert parameters receive no task-loss gradient for that token.
  • Selected gate values receive gradients through the weighted sum. With renormalization over selected softmax probabilities, the task-path gradient to unselected logits cancels; without that renormalization, unselected softmax logits can receive an indirect denominator gradient, though their expert parameters still receive none.
  • For renormalized top-1, the task path gives no local router gradient at all because the only weight is exactly one. Auxiliary balancing losses, router z-loss, noise, or specialized estimators are therefore especially important.

Classical auxiliary load-balancing loss

For a batch of T tokens under top-1 token-choice routing, define the observed routed-token fraction and the mean pre-selection router probability mass:

f_e = (1/T) Σ_t 1[argmax_j p_{t,j} = e] p_e = (1/T) Σ_t p_{t,e} L_balance = E Σ_e f_e p_e L_total = L_task + α L_balance

The assignment indicator in f_e comes from argmax/TopK and is nondifferentiable, so token counts alone cannot tell gradient descent how to alter router logits. In practice f_e is treated as a stopped-gradient statistic. The differentiable probability term p_e supplies router gradients: an expert with a high routed fraction is penalized for retaining high probability mass. For top-2, f_e can analogously count expert assignments out of Tk; implementations differ in whether first and second choices are weighted equally.

The factor E makes the ideal uniform value 1: if f_e=p_e=1/E, then E Σ_e f_e p_e=1. Complete concentration approaches E. The coefficient α controls the quality-versus-balance tradeoff and must be interpreted with the implementation's reductions across tokens, layers, and devices. It is usually small relative to the task loss: too little allows hot or dead experts; too much can erase useful specialization or distort the main objective.

Related router objectives

  • Router z-loss: penalizes large log-normalizers, commonly L_z = mean_t(log Σ_e exp(z_{t,e}))². It stabilizes router logits and numeric precision; it does not by itself guarantee balanced token counts.
  • Entropy regularization: adding -H(p_t) encourages higher-entropy, exploratory routing; adding +H(p_t) encourages sharper routing. High entropy can fight collapse but may also fight confident specialization, and entropy alone does not enforce equal realized loads after top-k.

Capacity and overflow

For T tokens, E experts, top-k routing, and capacity factor CF, a common per-expert capacity is:

C = ceil(CF · T · k / E)

The exact formula may use tokens local to an expert-parallel group and may round to kernel-friendly multiples. CF=1 reserves the uniform expected load; a larger factor reduces overflow at the cost of padding, memory, and wasted compute.

  • Token dropping: discard assignments beyond C; this saves bounded work but loses the expert transformation for those tokens.
  • Residual bypass: a dropped token continues along the residual stream, avoiding a zeroed representation but still skipping the MoE computation.
  • Second-choice routing: try the token's next expert if the first is full, as in capacity-aware top-2 schemes; the fallback may also be full.
  • Random token selection: when an expert is oversubscribed, randomly choose which tokens it accepts instead of always favoring the highest router scores. This spreads training opportunity but adds variance.
  • Dynamic/dropless buffers: allocate or communicate variable-sized expert batches. No token is dropped, but the hottest expert determines memory pressure and straggler time.

Balancing scope matters. Sequence-level balancing computes statistics or constraints within each sequence and can stop a long domain-specific sequence from monopolizing experts, but it may suppress legitimate within-sequence specialization and has noisy small samples. Global balancing over the batch or expert-parallel group is statistically smoother and hardware-relevant, but can hide that one sequence, language, or host is badly skewed. In distributed training, loads should be measured over the same group that actually performs the all-to-all.

Consider six tokens and three experts. Each row is a softmax router distribution:

Top-1 assignments. E1 receives {t1,t2,t6}, E2 receives {t3,t4}, and E3 receives {t5}. Therefore:

f = (3/6, 2/6, 1/6) = (0.500, 0.333, 0.167) p = ((2.25)/6, (2.25)/6, (1.50)/6) = (0.375, 0.375, 0.250) L_balance = 3[(0.500)(0.375) + (0.333)(0.375) + (0.167)(0.250)] = 3[0.1875 + 0.1250 + 0.0417] = 1.0625

The ideal uniform value is 1, so 1.0625 shows mild imbalance. If α=0.01, this batch contributes 0.010625 to the total objective under this reduction convention.

Top-2 assignments. Before capacity handling, E1 receives 3 assignments, E2 receives 6, and E3 receives 3, so the assignment fractions are f=(0.25,0.50,0.25) out of 12. Reusing the pre-selection p above gives L_balance=3(0.25·0.375 + 0.50·0.375 + 0.25·0.250)=1.03125. The renormalized weights in the table show exactly how the two selected expert outputs would be combined.

Apply capacity. With top-1 and CF=1, C=ceil(1·6·1/3)=2. E1 overflows by one assignment. If tokens are admitted by router score, t6 (E1 score 0.45) overflows after t1 and t2. Switch-style dropping can send t6 through only the residual path. A second-choice router tries E2 (score 0.40), but E2 is already at capacity in this top-1 snapshot, so it must try another allowed destination or drop/bypass. Random selection would retain a random two of {t1,t2,t6}. Dropless routing processes all three and accepts the imbalance.

For top-2 at CF=1, C=ceil(1·6·2/3)=4. E2 has six requested assignments and overflows by two while E1 and E3 each have room. A GShard-like capacity-aware policy may reject or reroute lower-priority second choices. Expert-choice with quota four instead lets each expert select up to four tokens directly, guaranteeing no expert batch exceeds four but not guaranteeing that every token receives the same number of experts. An auxiliary-loss-free router would keep the current model objective untouched and lower E1/E2 routing biases on subsequent batches according to their measured excess load.

Specialization versus uniformity

Perfectly uniform routing is a systems proxy, not the semantic objective. An expert may usefully specialize by language, domain, syntax, modality, or token type, and natural traffic is not uniform across those categories. Forcing every batch to be exactly uniform can erase this structure and hurt quality.

The operational goal is to separate learned specialization from harmful imbalance. A specialized expert can be valuable while still receiving enough varied updates and fitting within capacity. A hot expert is persistently oversubscribed, causes drops or stragglers, and may attract still more tokens through a feedback loop. A dead expert receives almost no tokens; it gets few task gradients, becomes undertrained, and then looks even less attractive to the router. Undertrained experts also waste stored parameters. Compare routing by semantic slice with capacity, gradient, and latency measurements before deciding that nonuniformity is a defect.

Active versus total parameters

An MoE model can have very large total parameter count while activating only a fraction for one token. Report both:

  • total parameters, relevant to storage and model loading;
  • active parameters/FLOPs, relevant to per-token compute;
  • expert memory distribution;
  • routing and all-to-all overhead.

A claim such as “more parameters at the same compute” omits communication, router, and serving costs.

Expert parallelism

Experts are sharded across an expert-parallel group. A typical layer performs:

  1. local router computation;
  2. count and pack tokens by destination;
  3. all-to-all dispatch;
  4. local expert MLPs;
  5. all-to-all return;
  6. weighted combine and restore token order.

Dispatch first counts and packs tokens by expert. Fixed-capacity implementations can use padded equal splits; dropless implementations often need variable all-to-all splits and exchange counts before payloads. Expert-parallel groups bound which devices participate and therefore define both communication cost and the relevant load-balancing population.

On each destination device, a grouped GEMM runs multiple differently sized expert matrices/batches efficiently. Tiny expert batch sizes waste accelerator throughput; hot experts create stragglers that stall the all-to-all return. Implementations overlap packing or communication with expert computation when dependencies and the network permit, but imbalance shortens the useful overlap window. See parallelism and distributed training for the surrounding process-group and collective design.

Serving

Serving MoE models requires all expert weights to be available across the group even though each token uses few experts. Low batch sizes create tiny expert batches and expose communication latency; variable routing makes tail latency less predictable. Popular experts can be replicated across devices at serving time to shorten queues or reduce cross-node traffic, but replicas require routing, placement, and memory-aware scheduling. See serving and distributed inference.

Failure modes

  • router collapse;
  • hot-expert overflow, token dropping, or step-time stragglers;
  • dead or undertrained experts receiving too little task gradient;
  • auxiliary loss overwhelming the main objective;
  • apparently balanced global counts hiding sequence- or domain-level collapse;
  • all-to-all dominating expert compute;
  • nondeterministic capacity behavior;
  • reporting active FLOPs while ignoring total memory;
  • confusing expert parallelism with data parallelism.
