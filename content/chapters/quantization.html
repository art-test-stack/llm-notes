Learning objectives

You should be able to explain floating-point formats, affine quantization, granularity, calibration, PTQ versus QAT, weight/activation/KV quantization, and why compression does not automatically imply latency improvement.

Precision before quantization

Numeric formats trade range, precision, storage, and hardware throughput:

  • FP32: large range and precision; common reference and accumulation format.
  • FP16: narrower exponent range; often needs loss scaling during training.
  • BF16: FP32-like exponent range with fewer mantissa bits; often easier for training.
  • FP8: several formats with different range/precision trade-offs; requires scaling and supported kernels.
  • INT8/INT4: quantized integer representations with explicit scales and zero points.

Mixed precision is not simply “make everything low precision.” Sensitive reductions, optimizer state, or accumulations may remain in a wider format.

Affine quantization

Affine quantization first clips a real value to x_c = clamp(x, α, β), rounds it to an integer code, and saturates any code outside the target range:

q = clamp(round(x_c / s) + z, q_min, q_max) x̂ = s (q - z)

For asymmetric quantization, s = (β - α) / (q_max - q_min) and z = clamp(round(q_min - α/s), q_min, q_max). The integer zero point makes real zero exactly representable when possible and uses the available codes efficiently for an off-center range. Symmetric signed quantization instead takes a = max(|α|, |β|), s = a/q_max, and z = 0, commonly using codes [-127, 127]. It simplifies kernels and avoids zero-point correction, but may waste range for skewed data.

Rounding-to-nearest contributes at most about s/2 error for an unclipped scalar; deterministic rounding can introduce bias, while stochastic rounding is unbiased in expectation but costs randomness. Clipping creates overload error, and saturation maps every value beyond the chosen range to an endpoint. With x_c = clamp(x, α, β), the signed error decomposes as:

x - x̂ = (x - x_c) + (x_c - x̂) clipping error rounding / grid error

The terms trade off: a tighter range gives a smaller s and less grid error for central values, but more clipping error in the tails.

Worked quantization-error example

Quantize the calibrated range [-1, 2] to unsigned 4-bit codes [0, 15]. Then s = 3/15 = 0.2 and z = round(0 - (-1/0.2)) = 5. For x = 0.34, q = round(0.34/0.2) + 5 = 7, so x̂ = 0.2(7 - 5) = 0.4 and x - x̂ = -0.06, entirely grid error. For x = 2.4, clipping gives x_c = 2 and saturation gives q = 15; x̂ = 2, so the 0.4 error is entirely clipping error.

Scale granularity

  • Per-tensor: one scale and zero point for the full tensor; minimal metadata, most vulnerable to heterogeneous channels.
  • Per-channel: a scale per weight output channel, or sometimes activation channel; better local fit, with scale application built into the kernel.
  • Per-group: a scale for each contiguous group of weights within a channel. Smaller groups reduce error but consume more scale metadata and work.
  • Per-token: a dynamically computed activation scale for each token row; follows token-to-token range changes but adds reductions and synchronization.
  • Blockwise: a scale per small multidimensional tile, used by block floating-point and microscaling formats; tile shape must match the GEMM layout.

Finer granularity generally improves accuracy, but scale loads, metadata, reductions, and layout conversions can erase the benefit unless the hardware kernel natively matches that granularity.

Calibration and range selection

  • Min/max: map the observed extrema to the code range. It is simple and preserves every calibration value, but one outlier can make the grid coarse.
  • Percentile clipping: choose lower and upper quantiles, accepting rare saturation to improve resolution for most values.
  • MSE-optimal range: search candidate clipping thresholds and minimize reconstruction error Σ(x - x̂)². The answer depends on the tensor and bit width.
  • KL selection: compare the original activation histogram with a quantized-and-expanded histogram and choose the range minimizing KL divergence; common in entropy calibration, but sensitive to histogram binning and sparse tails.

An activation calibration set should sample deployment domains, prompt styles, sequence lengths, positions, batch regimes, and important rare cases. Capture statistics at every quantized layer after normal preprocessing; enough tokens matter more than a large number of near-duplicate prompts. Outliers may be persistent channels, rare tokens, or transient positions, so inspect both maxima and frequency. Distribution shift can move ranges after deployment: dynamic scales, held-out stress sets, mixed precision, or recalibration are safer than assuming calibration extrema are permanent.

PTQ and QAT

  • Post-training quantization (PTQ): quantize a trained model using calibration data or weight statistics. It is cheap but sensitive to outliers and calibration mismatch.
  • Quantization-aware training (QAT): insert fake-quantization nodes in the forward pass: values are quantized and immediately dequantized, so computation remains floating point but experiences clipping and grid noise. Since round has zero derivative almost everywhere, the straight-through estimator usually passes gradients through the quantizer inside the clipping range and blocks or clips them outside. Learned or calibrated scales and weights then adapt to the deployed quantizer.

Weight-only quantization

Weight-only INT8/INT4 stores packed weights while activations remain FP16/BF16. It is attractive for memory-bound decode because it reduces persistent memory and weight traffic.

GPTQ-style PTQ

For a linear layer and calibration inputs X, GPTQ approximately minimizes output reconstruction error ||XW - XŴ||². It uses a layerwise second-order approximation with an input Hessian proxy H ≈ XTX. Columns or small blocks are quantized sequentially; after rounding one set of weights, off-diagonal information from an inverse or factorization of H compensates the remaining unquantized weights. Damping stabilizes ill-conditioned curvature. This is more informed than independent nearest rounding, but it is still calibration-dependent and the solve/order are approximations.

AWQ-style activation-aware quantization

AWQ observes that a small fraction of channels carrying large activation magnitudes are especially salient. It searches channel scaling and clipping choices that protect those weights before groupwise quantization. Algebraically, a diagonal scale can preserve a linear layer as XW = (X S-1)(SW): making salient weight rows larger before quantization lowers their relative rounding error while inversely scaling activation channels. The transform is chosen using calibration activations and folded into adjacent operations where possible; AWQ does not quantize weights solely by their own magnitude.

Groups, packing, and execution

  • Group size: 32 or 128 weights per scale is typical; smaller groups usually improve quality but increase metadata and scale operations.
  • Outlier channels: retain them at higher precision, give them finer groups, or rescale them. Each exception complicates layout and kernels.
  • Packing: INT4 values are packed into bytes or machine words in the exact tile order expected by the kernel; logical 4-bit storage is not useful if repacking occurs per request.
  • GEMM: a useful kernel loads packed weights, unpacks/dequantizes them in registers or shared memory, and immediately performs multiply-accumulate. Materializing a full FP16 weight tensor forfeits most bandwidth savings.

The quality/throughput optimum is workload-specific. Smaller groups and mixed-precision exceptions improve reconstruction, while larger uniform groups pack and vectorize more efficiently. Weight-only quantization often helps low-batch decode more than compute-heavy prefill.

Weight-and-activation quantization

Activations vary across tokens and often contain channel outliers, making W8A8 or FP8 harder than weight-only quantization.

SmoothQuant-style redistribution

SmoothQuant applies an exact diagonal reparameterization XW = (XS-1)(SW). For channel j, a common scale is proportional to max|X_j|α / max|W_j|1-α. This divides activation outliers by S and moves their range into the corresponding weight rows, whose distributions are easier to quantize per channel. Calibration estimates activation maxima; α controls how much difficulty is transferred from activations to weights.

Dynamic per-token INT8 scaling reduces error when token ranges differ, at the cost of computing a maximum and applying a scale for each row. INT8 uses uniform integer grids and typically integer dot products; FP8 retains exponent bits, offers more dynamic range, and commonly uses tensor or block scales, but its benefit requires native FP8 matrix units and compatible formats. Layer normalization, softmax, attention score reductions, embeddings, output heads, and tensors with extreme outliers are often kept or accumulated in BF16/FP16/FP32. Products may be low precision while partial sums use INT32 or a wider floating type; insufficient accumulation precision can overflow or compound error even when operands are well quantized.

KV-cache quantization

The cache grows linearly with layers, batch, sequence length, KV heads, and head dimension. Reducing FP16 cache entries to 8 or 4 bits can roughly halve or quarter payload bytes, increasing context capacity and reducing the memory bandwidth spent reading old K/V during decode. Scale and zero-point metadata make real savings slightly smaller.

  • Granularity: per-head scales are cheap but coarse; per-channel scales follow persistent feature outliers; per-token or token-block scales follow temporal variation but add metadata and online reductions. Practical layouts combine these axes.
  • Keys versus values: key error perturbs attention logits before softmax and can change which positions are selected; value error perturbs the weighted result. Their sensitivity differs by layer and task, so K and V may deserve different bit widths, clipping, or granularity.
  • Long context: old cache entries are reused at every later step. Error does not simply add linearly, but small logit perturbations among many competing positions can hurt retrieval at long distances; test needle retrieval and generation quality at the maximum deployed context.
  • Kernels: paged-attention and fused decode kernels must read the packed layout, load scales cheaply, and dequantize in registers during the attention computation. A fallback that expands the cache first may increase latency and workspace despite lower stored bytes.

QAT and QLoRA

QAT changes trainable weights under fake-quantization noise; QLoRA instead freezes a quantized pretrained base and trains low-rank adapters in a wider compute dtype. QLoRA commonly stores base weights in NF4, a 4-bit codebook designed for approximately normal weight distributions rather than a uniform integer grid. At each linear operation the base blocks are dequantized for computation, and the adapter update is added; gradients and optimizer state are needed only for adapters, though activations still consume memory.

Double quantization quantizes the blockwise scale constants themselves, reducing scale metadata. It is separate from the NF4 codebook. QLoRA is a memory-efficient fine-tuning scheme, not ordinary QAT: the frozen base codes do not learn through a straight-through estimator, and inference speed still depends on whether deployment kernels execute the chosen packed format efficiently.

Training and optimizer state

Quantized optimizers or low-precision moments reduce training memory, but update stability and accumulation matter. Keep master weights, reductions, or selected states wider when their small updates would vanish at the storage precision.

Pruning

  • Unstructured: remove individual weights by magnitude, gradients, or second-order saliency. It yields flexible sparsity and good compression, but irregular indices and memory accesses often lose to dense GEMM.
  • N:M semi-structured: keep exactly N nonzeros in each group of M weights, such as 2:4. This constrains pruning quality but can match accelerator sparse tensor-core formats.
  • Structured: remove complete channels, MLP neurons, attention heads, layers, or rectangular blocks. Shapes shrink and dense kernels remain usable, but whole structures can be more damaging than the same number of isolated weights.

Nominal zeros are not speedup. The runtime needs the exact sparse format, supported dimensions, a sparse kernel faster than dense at the achieved sparsity, and low encoding/dispatch overhead. One-shot pruning may work at modest ratios; aggressive pruning usually needs recovery training or iterative prune-and-retrain so remaining parameters adapt.

Distillation

  • Logit distillation: minimize T² KL(softmax(z_teacher/T) || softmax(z_student/T)), often mixed with ground-truth cross-entropy. Temperature T > 1 exposes relative probabilities among non-target tokens; the T² factor keeps gradient scale comparable.
  • Sequence-level: train on sequences decoded or sampled from the teacher. It transfers the teacher's preferred output distribution without storing every logit, but decoding collapses some uncertainty and exposes the student to teacher-generated trajectories.
  • Representation matching: regress selected hidden states, projected features, attention maps, or attention logits. Different widths or head counts require explicit layer alignment or learned projections, adding objectives that may conflict with task loss.
  • Reasoning-data distillation: fine-tune on teacher solutions, rationales, critiques, or verified traces. Filtering by final answer and process checks matters because fluent rationales can still contain invalid steps.

Distillation changes the learned function or architecture rather than merely its representation. A student can inherit factual errors, biases, reward hacking, stylistic artifacts, and overconfidence from the teacher; use independent labels, verifiers, adversarial slices, and ground-truth evaluation rather than treating teacher agreement as correctness.

Hardware execution and benchmarking

Compression is fewer stored bits; hardware speedup is less end-to-end time or more useful work per second. The latter requires compatible layouts and kernels throughout the serving path.

  • Packed memory: report actual allocated bytes, including scales, zero points, sparse indices, padding, duplicated shards, and allocator fragmentation—not just bits per logical weight.
  • Effective bandwidth: divide useful model/cache bytes by measured time and compare with achievable device bandwidth. Unpacking, scale loads, and poor coalescing can make compressed bytes cheap to store but expensive to consume.
  • Kernel coverage: identify quantized GEMMs and attention kernels plus every fallback, cast, repack, graph break, and collective. One unsupported shape can dominate latency.
  • Workload shape: prefill is often compute-heavy; single-token, low-batch decode is often bandwidth-heavy. Batch size, prompt length, generated length, hidden dimensions, parallelism, and speculative acceptance all change the result.
  • End to end: measure time to first token, inter-token latency, request latency percentiles, peak memory, throughput, energy, and goodput at an explicit service-level objective. Include tokenization, scheduling, communication, and output handling where production does.

Always pair systems metrics with perplexity, task capability slices, long-context retrieval, calibration-shift stress tests, and identical quality constraints. A smaller model or cache that admits a larger batch can improve serving goodput even if one request is not faster; conversely, tensor-parallel scale traffic or collectives can hide gains in distributed inference. See kernel optimization for roofline and fusion details and speculative decoding for interacting decode trade-offs.

Failure modes

  • calibration data does not match deployment;
  • activation outliers saturate the range;
  • one global scale destroys small channels;
  • dequantization materializes large temporary tensors;
  • unsupported kernels fall back to slower paths;
  • quality measured only on average perplexity;
  • pruning produces nominal sparsity with no hardware speedup;
  • comparing memory savings at different model quality.
